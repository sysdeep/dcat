# Prop 1

2026.11

Проанализировав тек. набор баз выявлено

- база в sqlite занимает немало места, отчасти из-за неправильных типов данных на идентификаторы, но тем не менее - приходится вести несколько баз по несколько томов в них. На практике есть набор из 5 BDRom томов на 130Мб.
- необходимость sqlite обусловлена наличием поиска, других объективных причин нет.

## Предложение

- единая база
- записывать 1 том в 1 файл в бинарном формате с сжатием.
- вести индексный файл всех томов
- в UI отображать привычный интерфейс - список томов и список файлов в каждом

Каждый том хранится в бинарном формате с сжатием(например bss) при чтении загружается полностью в память, при сохранении полностью выгружается в файл. По памяти - только кол-во элементов в томе, может быть много - но конечно.

Индексный файл - содержит описание и атрибуты томов и ссылку на файл тома. При выборе тома - подгружается в память файл тома и отображается. При чтении загружается полностью и выгружается тоже полностью при правках.

Поиск - последовательно открывается файл тома и просматриваются записи.

Баз можно по прежнему вести несколько, в зависимости от содержимого. Также - тома можно группировать внутри одной базы.

Таким образом - в рамках одной базы можно добавлять сколько угодно томов в эффективном формате, а описательная часть описана отдельно в индексном файле. В таком варианте загружаться в память будет только индексный файл и 1 том, и уже неважно сколько томов в наборе.
